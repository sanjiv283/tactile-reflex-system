## RTL changes (the only functional changes to the design)

| File | Change | Why | Evidence |
|---|---|---|---|
| `rtl/uart_rx.v` | after a framing error or reset, wait for 4 consecutive idle clocks (`wait_idle`) before re-arming | the new framing test showed spurious bytes after a break, and that the two-flop synchroniser's reset value makes a line held low across reset release look like a new start bit | `tb_uart_framing` (45 assertions); mutants M27, M28, M35 |
| `rtl/reset_sync.v` (new) | reset synchroniser: asynchronous assert, synchronous release | board reset key was used raw | `tb_debounce`; M40, M41 |
| `rtl/button_debounce.v` (new) | debounced, edge-triggered clear key: one pulse per deliberate press; a key held through reset does not count (`warm` counter, `armed`) | clear key was undebounced and level-sensitive | `tb_debounce` (35), `tb_reset_recovery` (44); M36, M37, M38 |
| `rtl/de2_115_top.v` | uses `reset_sync` and `button_debounce` (`DEBOUNCE_CLKS` = 1,000,000 on the board); e-stop path stays undebounced | CDC and key hardening | `tb_reset_recovery`; M26, M39 |
| `rtl/tactile_reflex_top.v` | two-flop synchroniser on `adc_miso` | CDC hardening | `tools/cdc_check.py`. **Side effect: the sampling point moves 2 clocks earlier and the first data bit is sampled only 20 ns after chip-select falls: hazard H-16, an unresolved hardware blocker (needs the datasheet and a scope; decision pending)** |

No other RTL file changed. The 12 original testbenches and the experiments still pass unchanged apart from added reporting fields and monitor checks.
